\chapter{Introduction}
\label{chapter:introduction}

Currently, most scheduling applications supply the options for defining tasks with known start time and length. Sometimes even allows for repetition. These restrictions might not be enough for a lot of people. Especially, when those people have problems with time management. Hence, we want to define a scheduling application, which also allows for soft time constraints. Meaning tasks
\begin{itemize}
    \item have broad time spans in which it is acceptable to schedule them,
    \item may have different time spans with different levels of preferability,
    \item the possibility of not scheduling tasks at all,
    \item relations between tasks and
    \item the option to define locations to a task to reduce travel time.
\end{itemize}
This application should be able to take natural language inputs and create tasks from that descriptive inputs, before being scheduled using some form of constraint solving. To narrow the vast range of possible verbal definitions of such a task to as few as possible, we introduce our \Ac{IR}. We will give various reasons why such a representation is necessary. The simplest being, having constraints to give to a solver in a performant manner and defining the language, while ensuring the most efficient representation.

\section{Motivation}
\label{sec:introduction:motivation}
Scheduling is known to be a hard problem, especially constraint scheduling as for example in assigning restricted resources like rooms to given professors/courses at a university~\cite{bib:2017-diveev}. With this approach we want to enable the definition of tasks in a minimal form, whilst maintaining expressivity to allow efficient solving in future work. \\
We specifically do not define or implement a solver, but only provide the needed framework to bridge the gap between possible word-ambiguities, and solvable constraints.

\section{Objectives and Approach}
\label{sec:introduction:objectives}
The objective consists of
\begin{itemize}
    \item finding a language, which provides ample expressivity while remaining relatively simple,
    \item giving a notion of solution for a given problem (input language),
    \item defining how to compare given solutions and
    \item showing the relation between the constraints of the language and constraints of solvers.
\end{itemize}
We evaluated several approaches to identify the most promising one. It is safe to say that this is not the only solution as there are ample possibilities on defining such constraints. We give various reasons as to why this final set of constraints are superior to previously considered options and differing implementation ideas.

\section{Outline}
